# Архив бизнес-планов PDF и Excel

Архив хранит готовые отчёты компании, например бизнес-план UZGERMED PHARM на 36 месяцев. У каждой версии есть название, начало и конец периода, дата загрузки, номер версии и два исходных файла: PDF и XLSX. Версия становится готовой только после успешной загрузки обоих файлов.

Это архив подготовленных документов. Сервер не пересчитывает формулы XLSX, не формирует из Excel новый PDF и не переносит бизнес-план в фактические платежи, остатки, бюджет или платёжный календарь. PDF и XLSX необходимо подготовить и сверить перед загрузкой. Для нового расчёта загрузите новую пару документов.

## Загрузка и получение

1. На сайте выберите компанию и откройте раздел бизнес-планов. В боте откройте этот раздел в личной переписке после привязки Telegram к учётной записи сайта.
2. Укажите название и период, который описывают документы. Для модели на 36 месяцев укажите реальные даты первого и последнего месяца модели. Период может быть между 2000 и 2100 годами, не больше 1830 дней.
3. Загрузите PDF и XLSX, каждый не больше 20 МБ. Название файла не должно содержать путь. Сервер проверяет PDF-сигнатуру и структуру обычного XLSX без макросов; зашифрованные книги не принимаются. Суммарный размер распакованного XLSX ограничен 100 МБ, одной части — 30 МБ.
4. Пока отсутствует один файл, версия остаётся черновиком. Автор с правом импорта может продолжить свою загрузку; другие пользователи черновик не получают. В боте для продолжения используется список незавершённых загрузок.
5. После загрузки пары версия доступна пользователям с правом экспорта в этой компании. Можно скачать PDF или Excel. Готовую версию не заменяют: исправления публикуются новой загрузкой. Повтор того же запроса и тех же байтов не создаёт дубликата.

Период отчёта и дата загрузки — разные поля. Фильтр периода выбирает документы, период которых пересекается с выбранным диапазоном, и не обрезает файлы. Фильтр даты загрузки выбирает версии, завершённые в этот календарный день по Ташкенту. Для черновика показывается дата создания; после завершения пары дата обновляется и фиксируется.

## Доступ и хранение

Просмотр списка и скачивание используют действующее право `export`; создание и загрузка — `import`. Право учитывает роль именно в выбранной компании и действующее замещение. Учредитель читает готовые версии; администратор холдинга загружает файлы лишь при отдельном финансовом назначении. Учётная запись должна быть активна; временный пароль сначала меняется на сайте.

Каждый запрос проверяет доступ заново. Бот использует свой сервисный ключ и идентификатор привязанного пользователя; знание номера отчёта или компании не открывает файлы. Группы Telegram не используются для загрузки и выдачи этих документов. После отключения пользователя, отзыва его доступа или компании новые скачивания блокируются. Уже скачанная пользователем копия остаётся у получателя.

Байты файлов находятся в закрытых таблицах `report_archive_files` базы данных; метаданные — в `report_archives`. Они сохраняются при перезапуске сервиса с временной файловой системой и входят в полную резервную копию базы PostgreSQL или SQLite. Публичных ссылок на хранилище и кэша Telegram `file_id` для обхода проверки доступа нет. Реальные PDF, Excel, базы и резервные копии не входят в публичный GitHub-репозиторий.

## API

Браузер использует обычную сессию и CSRF для записи. Все запросы выполняются в выбранной компании; параметр `company_id` и заголовок `X-Company-ID`, если переданы вместе, должны совпадать.

| Метод | Адрес | Назначение |
|---|---|---|
| GET | `/api/report-archives?company_id=...` | Готовые версии и собственные черновики; `can_upload` показывает право создания |
| POST | `/api/report-archives` | Черновик: JSON `company_id`, `title`, `period_start`, `period_end`, `request_key` (UUID) |
| PUT | `/api/report-archives/{id}/files/{format}?company_id=...` | Исходные байты файла, `format=pdf\|xlsx`, имя в `X-Filename` с UTF-8 URL-кодированием |
| GET | `/api/report-archives/{id}/files/{format}?company_id=...` | Скачивание файла с проверкой прав и `Content-Disposition` |

GET списка также принимает `date_from`, `date_to` и `uploaded_on` в формате `YYYY-MM-DD`. Ответ: `{items: [...], can_upload: true/false}`. Метаданные элемента и ответы POST/PUT: `id`, `title`, `company_id`, `company_code`, `company_name`, `period_start`, `period_end`, `uploaded_at` (UTC ISO 8601 со смещением), `version`, `formats`, `status`, `can_upload`. У элемента `can_upload` разрешает продолжение собственного черновика, у списка — создание новой версии.

Бот вызывает те же адреса с префиксом `/api/bot/v1/report-archives`, HTTP Basic и обязательным query-параметром `telegram_user_id` во всех запросах. Для GET/PUT файлов обязательно передаётся выбранный `company_id`. Список по умолчанию содержит только готовые версии; `include_drafts=true` дополнительно включает собственные черновики пользователя с правом импорта. Список доступных компаний: `GET /api/bot/v1/report-archive-companies?telegram_user_id=...` → `{linked, items: [{id, code, name, can_upload}]}`.

`request_key` уникален в пределах компании. Повтор с тем же ключом, автором и метаданными возвращает исходную запись; другие метаданные дают 409. Повтор PUT с тем же содержимым возвращает исходный результат; изменение файла готовой версии даёт 409. Записи и завершение пары сериализованы общей транзакционной блокировкой приложения. При потоковой загрузке права повторно проверяются непосредственно перед записью.

Проверки: `python -m unittest tests.test_report_archives -q`. CI запускает их отдельно с временной SQLite и с тестовой PostgreSQL. Тестовые файлы синтетические: они проверяют права, изоляцию компаний, черновики, повтор запросов, сохранность пары, фильтры дат и ограничения файлов.
