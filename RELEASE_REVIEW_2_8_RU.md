# Проверка UZGERMED 2.8.0 — 24.09.2026

## Исправлено при ревью

- Не хватало ролей оператора и инвестора. Добавлены серверные права и пункты интерфейса; права планирования отделены от права устанавливать бюджетные лимиты.
- Директор не мог редактировать финансовые данные и пороги согласования. Теперь может; управление сотрудниками остаётся у администратора. Самосогласование и подтверждение обеих ступеней одним человеком запрещены.
- Годовая книга планов больше 64 КБ отклонялась общим ограничителем JSON-запросов. Для этого upload используется лимит 5 МБ, как для импорта операций.
- Два заранее открытых предпросмотра могли повторно подтвердить один файл. Повторная проверка выполняется под транзакционной блокировкой при commit.
- Импорт мог затереть план, изменённый после предпросмотра. Теперь сравниваются версии каждого затрагиваемого месячного сценария; конфликт откатывает импорт целиком.
- Парсер XML планов переведён на defusedxml, ограничен номер строки. Права после длительной загрузки повторно проверяются перед записью.
- При недоступной БД запись технического HTTP-журнала могла перекрыть исходную ошибку. Ошибка БД теперь возвращается без подробностей SQL. Успешный бизнес-результат не подменяется ошибкой вторичного журнала.
- FastAPI обновлён с 0.128.2 до 0.141.1, Starlette — с 0.50.0 до 1.7.0 после обнаружения известных уязвимостей старой версии.
- Добавлен отдельный `/ready` с проверкой PostgreSQL. Compose использует его для проверки готовности.
- Добавлен Render Free blueprint; облачный запуск запрещает SQLite, подключение без TLS, временный JWT-ключ и публикацию без восстановленного администратора.

## Что ещё требуется для публикации

- Завершить вход владельца в Render и Neon, создать бесплатные ресурсы и перенести данные в пустую облачную базу.
- Docker локально не установлен. Проверка сборки контейнера добавлена в GitHub Actions; её фактический результат нужно проверить после push, до облачной публикации.
- Проверить облачный адрес, TLS, `/ready`, права, экспорт, вложения и восстановление после сна Render. До этого нельзя считать облачный перенос завершённым.
- Собственный домен не зарегистрирован. Бесплатный `onrender.com` назначает Render при создании сервиса; имя заранее не гарантировано.
- Независимые автоматические резервные копии облачной БД не настроены. Разделы P&L/Balance, банковский обмен и 1С остаются вне этой поставки.
- Нет разграничения по отдельным компаниям/счетам внутри финансовой роли. Сценарии А/Б/В выбираются вручную; автоматические пороги не определены.
