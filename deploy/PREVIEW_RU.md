# GitHub и временный просмотр

## Как увидеть изменения

На странице входа и в приложении есть кнопка **«Версия … · Что нового»**. В ней показан список изменений текущей версии. Открытая вкладка раз в минуту проверяет новую версию, когда видима. При обновлении появляется кнопка **«Обновить страницу»**; незавершённые формы автоматически не перезагружаются.

Исходный код: https://github.com/SHAN120186/CASH_Zuma. Каждый законченный этап сохраняется отдельным коммитом. GitHub Actions проверяет frontend, backend и запуск временного просмотра при push и pull request. Реальные данные и секреты в публичный репозиторий не отправляются.

## Запуск временного HTTPS-адреса

Для ежедневного ручного запуска используйте **OPEN_SITE.bat** или ярлык «Запустить UZGERMED» на рабочем столе. Он запускает существующую базу и локальный сервер, затем туннель и открывает текущую ссылку. Если сайт уже работает, он открывается без повторного запуска служб. Ссылка сохраняется в `PUBLIC_URL.txt`; после полного перезапуска туннеля она меняется. Ярлык не включает компьютер и не запускается автоматически при входе в Windows. Запуск браузера не подтверждает доступность туннеля из всех сетей.

В случае ошибки окно останется открытым с пояснением. Журналы запуска находятся в `.runtime/`. При отсутствии `config.local.env` запуск останавливается, чтобы не создать новую пустую базу.

Раздельный запуск, если нужен:

1. Запустите обычный локальный проект, чтобы PostgreSQL и worker работали.
2. Убедитесь, что законченная версия проверена, закоммичена и отправлена в GitHub.
3. Запустите `START_WEB_SERVER.bat`. Требуются установленный cloudflared и Python-окружение проекта.
4. Откройте адрес из `PUBLIC_URL.txt`. Вход — с существующей учётной записью проекта.

Это временный туннель к данному компьютеру, а не отдельный круглосуточный хостинг. Компьютер и процессы должны оставаться включёнными. При полном перезапуске туннеля адрес меняется. Для постоянного сервера нужны VPS/облачный аккаунт и домен; пример размещения — `compose.yaml`.

Временный API слушает только `127.0.0.1:8002`. Туннель даёт HTTPS, cookies помечены Secure, разрешён конкретный Host/Origin. Сервер использует текущую базу и каталог документов: внесённые через временный адрес операции изменяют рабочие данные. Дополнительный worker не запускается. Локальный сервер на 8001 продолжает работать.

## Публикация следующей версии

1. Внести изменения, обновить `release.json` (версию, дату и описание).
2. Выполнить подходящие проверки: `node --test frontend/tests/*.test.js`, сборку из `frontend`, `python tests/test_site.py`, `python -m unittest discover -s tests -p test_preview.py`.
3. Проверить `git diff` и состав коммита, выполнить `git commit` и `git push`.
4. Запустить `UPDATE_PREVIEW.bat` или `.venv-local/Scripts/python.exe deploy/preview.py --update`.
5. Проверить сайт, `/health` и `/version.json`. Передать пользователю ссылку на коммит и временный адрес.

Сервер берёт снимок из Git, а не файлы, которые сейчас редактируются. Обновление перезапускает только API; адрес туннеля сохраняется. Возможен короткий перерыв запросов. Если новый API не запускается, возвращается предыдущий код. Изменения схемы БД автоматически назад не откатываются: перед миграцией нужен отдельный бэкап.

Состояние: `python deploy/preview.py --status`. Остановка: `python deploy/preview.py --stop` либо Ctrl+C в окне запуска. Логи и снимки находятся в `.runtime/preview/`, исключённом из Git.
