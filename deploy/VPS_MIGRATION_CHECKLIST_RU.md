# Перенос UZGERMED на VPS: готовность и границы

## Что подтверждено сейчас

- Рабочая база — PostgreSQL; приложение и база пока работают на ноутбуке.
- Адрес `*.trycloudflare.com` — временный туннель. Это не купленный домен и его имя может измениться.
- Репозиторий содержит Docker Compose, PostgreSQL, Caddy для HTTPS и проверку `/health`.
- До получения адреса VPS, SSH-доступа и домена перенос не выполняется.

## Что нужно получить от владельца

1. IP VPS, SSH-пользователь и способ входа по ключу.
2. Домен и доступ к его DNS. Если домена нет, сначала можно проверить по IP без публичного запуска.
3. Подтверждение, какая база является основной в момент переключения.
4. Окно обслуживания, когда сотрудники прекращают запись в старую систему.

Секреты и пароли передаются через защищённый канал и хранятся только в `.env` на VPS. Их нельзя добавлять в Git.

## Минимальные ресурсы

- Linux x86-64/ARM64 с Docker Engine и Compose;
- 2 vCPU, 2 ГБ RAM, 20 ГБ SSD для пилота;
- порты 80/443 наружу; PostgreSQL наружу не публикуется;
- отдельное место для резервных копий.

## Порядок переноса

1. На ноутбуке проверить Git, тесты, сборку и создать две копии: `pg_dump -Fc` и каталог данных/документов.
2. Восстановить копию в отдельную тестовую базу и сверить количество пользователей, счетов, операций, заявок и итоговые остатки.
3. Поднять Compose на VPS, заполнить `.env`, проверить `/health` и вход по IP/временному закрытому адресу.
4. Настроить DNS и HTTPS Caddy, затем проверить Host/Origin, Secure-cookie и роли.
5. В окно переключения остановить запись на ноутбуке, сделать свежую копию, восстановить её на VPS и повторить сверку.
6. Переключить пользователей только после проверки. Старую базу оставить только для чтения как резерв до приёмки.

## Проверка после запуска

- вход и 60-минутная сессия;
- счета и остатки по UZS/USD/EUR;
- создание, согласование и оплата тестовой заявки;
- Cash Flow по компаниям и сценариям A/B/V;
- импорт в режиме предпросмотра;
- документы, Excel/PDF, журнал;
- автоматический перезапуск после reboot;
- ежедневный backup и пробное восстановление.

## Откат

Если сверка не проходит, DNS возвращается на предыдущую точку, VPS переводится в режим без записи, а работа продолжается на исходной базе. Две базы нельзя одновременно использовать для ввода: это создаст расходящиеся данные.
