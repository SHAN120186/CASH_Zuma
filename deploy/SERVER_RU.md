# Размещение на сервере: PostgreSQL + HTTPS

Этот файл — инструкция и шаблон конфигурации, а не подтверждение выполненного размещения. Docker, PostgreSQL, сертификат и доступ Google Drive в среде сборки не запускались. Перед реальным учётом необходимы проверка на вашем сервере и приёмка. Сервер может быть вашим внутренним сервером; облачный хостинг не обязателен.

## Что нужно от владельца

Постоянно работающий сервер с Docker Engine + Compose, доменное имя, DNS и разрешённые порты HTTPS. Для закрытого контура предпочтителен VPN; публичный доступ должен быть отдельно согласован. Базу PostgreSQL не публикуйте наружу. Установка не переносит существующие данные SQLite автоматически: сначала определите, где будет основная база, либо выполните контролируемый перенос с проверкой сумм.

## Установка

Скопируйте весь проект на сервер в закрытую папку. Скопируйте `.env.server.example` в `.env`, подставьте **свой** домен и email. `cashflow.example.com` — только пример, это НЕ созданный сайт. Для пароля БД используйте случайную hex-строку, чтобы не вводить специальные символы в URL подключения:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Не оставляйте пароль-пример. Файл `.env` должен читаться только администратором. Заполните DNS A (и корректный AAAA, если используется) адресом сервера. Доступны 80 и 443 для Caddy; проверьте, что их не занимает другой сервис. Для внутреннего домена и закрытой сети настройте доверенный корпоративный сертификат вместо публичного ACME — этот шаблон рассчитан на публично проверяемый DNS.

```bash
docker compose config --quiet
docker compose up -d --build
docker compose exec web python manage.py create-admin
```

Последняя команда интерактивно создаёт администратора. После неё входите на `https://ВАШ-ДОМЕН`, используя заданный пароль. Автосозданного общего пользователя нет. Пока администратор не создан, на странице входа войти некому.

```bash
docker compose ps
docker compose logs --tail=100 web proxy db
```

Сервисы `web` и `db` не публикуют свои порты на хост. В интернет смотрит только reverse proxy. Приложение использует Secure-cookie, проверяет Origin и разрешённые Host. Заголовкам reverse proxy доверяется только IP Caddy `172.29.113.3`. Если подсеть `172.29.113.0/24` конфликтует с сетью организации, согласованно измените сеть в `compose.yaml` и trusted proxy в `Dockerfile` — не заменяйте доверенные адреса на `*`.

База — том `postgres_data`, импортированные модели — `model_data`. **Не выполняйте `docker compose down -v`: это удаляет тома и учёт.** Исходная модель попадает в приватный образ при сборке; не публикуйте образ.

## Google Drive (опционально)

После настройки сервисного аккаунта по README положите ключ на сервер в `secrets/google-service-account.json`. Сделайте его доступным для uid 10001 (процесс приложения) только на чтение; не делайте world-readable. Затем:

```bash
docker compose -f compose.yaml -f compose.drive.yaml up -d --build
```

Далее используйте такой же набор `-f` при управлении этой установкой. Кнопка в FinModel делает импорт по запросу. Автосинхронизации и записи обратно в Google Drive нет. Пример отдельного ручного запуска:

```bash
docker compose -f compose.yaml -f compose.drive.yaml exec web python manage.py sync-drive
```

## Резервное копирование

Пример для Linux-shell (не PowerShell старых версий, который может изменить бинарный поток):

```bash
mkdir -p backups
chmod 700 backups
docker compose exec -T db pg_dump -U zuma -d zuma -Fc > backups/zuma_database.dump
# Снимок файлов моделей: выполните рядом с резервной копией БД в окно без новых импортов.
docker compose cp web:/app/data/models backups/models
```

Создавайте уникальные датированные имена, не перезаписывайте единственную копию. Храните резервные копии вне сервера в защищённом хранилище. Отдельно сохраните конфигурацию и документы по управлению ключами. Восстанавливайте в отдельную тестовую БД и сверяйте пользователей, остатки, суммы, заявки и версии модели; пример команды для подготовленной чистой тестовой БД:

```bash
# TARGET_DB должна быть заранее созданной тестовой базой, НЕ рабочей zuma.
cat backups/zuma_database.dump | docker compose exec -T db pg_restore -U zuma -d TARGET_DB --no-owner
```

Это пример команды, не автоматическая политика резервирования. Настройте периодичность, хранение, мониторинг ошибок, тест восстановления и ответственного администратора. Вне окна обслуживания не восстанавливайте поверх работающего учёта.

## До допуска пользователей

Проверьте реальный HTTPS-сертификат, Secure/SameSite-cookie, недоступность БД из интернета, ограничения ролей, смену/отзыв пароля, защиту от перебора, сетевые таймауты, резервные копии и восстановление. Выполните тесты на PostgreSQL, проверку конкурентных оплат/лимитов и независимый обзор безопасности. Выберите и закрепите проверенные версии/образы после обновления безопасности. Контейнер `web` пока один: горизонтальное масштабирование и миграции схемы отдельно не настроены.
