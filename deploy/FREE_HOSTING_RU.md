# Бесплатное размещение UZGERMED: Render + Neon

Обновлено для версии 2.9.5. Этот документ и `render.yaml` описывают конфигурацию, но сами по себе не означают, что сайт уже размещён.

## Что получится

- Render Free запускает Python API и собранный Vue-интерфейс из этого репозитория.
- Neon Free хранит PostgreSQL отдельно от процесса сайта. Операции, планы А/Б/В, пользователи, заявки и вложения документов находятся в базе.
- Render назначает HTTPS-адрес `имя.onrender.com`. Доступность имени `uzgermed` определяется при создании сервиса; домен `.uz` или `.com` не приобретается.
- После успешного переноса ноутбук можно выключать. Бесплатный Render засыпает после 15 минут без посетителей; первый запрос после простоя запускает его снова. Это не гарантированный круглосуточный сервис без задержек.
- Бесплатный Render PostgreSQL здесь не используется: его бесплатная база имеет ограниченный срок жизни.
- Не добавлять платный диск, worker, cron, платный план или карту. Если провайдер требует оплату — остановиться и обсудить с владельцем.

Условия провайдеров следует перепроверять перед размещением:
[Render Free](https://render.com/docs/free),
[Neon Free](https://neon.com/blog/how-to-make-the-most-of-neons-free-plan),
[актуальные квоты Neon](https://github.com/neondatabase/website/blob/main/content/faqs/free-plan-limits-and-quotas.md).

## Настройка уже созданного сервиса Render

Если сервис был создан вручную из Docker, без `render.yaml`, второй сервис создавать не нужно. Все настройки задаются на существующем.

1. Открыть сервис → **Settings → Environment** и добавить переменные:

   | Переменная | Значение |
   |---|---|
   | `UZGERMED_HOSTING` | `render` |
   | `DATABASE_URL` | строка подключения Neon с `sslmode=require` |
   | `JWT_SECRET` | случайная строка не короче 32 символов, задаётся один раз и сохраняется |
   | `COOKIE_SECURE` | `1` |
   | `TZ` | `Asia/Tashkent` |

   `DATABASE_URL` и `JWT_SECRET` — секретные значения. Их нельзя записывать в репозиторий, в журнал или в переписку.
2. **Docker Command** не переопределять: запуском управляет `deploy/entrypoint.sh` из образа.
3. `PORT` задавать не нужно — Render назначает его сам, приложение использует назначенный порт.
4. `ALLOWED_HOSTS` и `PUBLIC_ORIGIN` вручную не задавать: сервер вычисляет их из `RENDER_EXTERNAL_HOSTNAME`. Собственный домен указывается позже отдельной переменной `PUBLIC_ORIGIN` вида `https://домен`.
5. **Manual Deploy → Deploy latest commit**.

Начиная с версии, где добавлено распознавание платформы, сервис на Render **не запустится без внешней PostgreSQL с TLS и постоянного `JWT_SECRET`**: в журнале появится строка `Render start aborted: …` с причиной и без секретов. Прежнее поведение — тихий запуск временной SQLite на исчезающем диске контейнера — устранено намеренно: такая база теряется при каждом перезапуске. Распознавание работает и без `UZGERMED_HOSTING`, по собственным переменным платформы `RENDER` и `RENDER_SERVICE_ID`, поэтому вручную созданный сервис тоже проходит облачную проверку.

Смена `JWT_SECRET` завершает все сессии пользователей. Менять его без необходимости не следует.

## Порядок переноса существующей базы

1. Войти в Render и Neon под аккаунтами владельца. Пароли, строки подключения и JWT-ключи не публиковать в GitHub или чате.
2. Создать **Neon Free**, PostgreSQL **18** (или использовать уже созданную базу), регион рядом с приложением, если доступен. Выбрать прямое подключение без pooler для `pg_restore`; TLS обязателен. Проверить квоты в консоли. Клиенты `pg_dump` и `pg_restore` должны поддерживать старшую версию целевого сервера: клиент 17 не создаёт копии сервера 18.
3. Перед окончательным переносом временно остановить ввод операций на старом сайте, закрыть старый публичный туннель. Не разрешать параллельную запись в две независимые базы.
4. Создать свежий dump рабочей PostgreSQL и проверить восстановление:

   ```powershell
   .\.venv-local\Scripts\python.exe tests/verify_backup.py
   ```

   Скрипт использует отдельную временную базу, сравнивает финансовые таблицы, планы, суммы и содержимое вложений, затем удаляет только эту временную базу. Dump остаётся в приватной папке `backups`.
5. Восстановить dump **в пустую** Neon-базу совместимой утилитой PostgreSQL 18:

   ```text
   pg_restore --no-owner --no-privileges --single-transaction --exit-on-error --dbname neondb PATH_TO_PRIVATE_DUMP
   ```

   `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGSSLMODE=require` задаются приватно для процесса. Не помещать пароль в командную строку. Предварительно убедиться, что адрес назначения — Neon, а не рабочая локальная база. При наличии существующих таблиц не использовать `--clean` и не удалять их: выбрать новую пустую базу. Проверить число строк, остатки по валютам, планы А/Б/В и контрольные суммы документов после восстановления.
6. В Render открыть **New → Blueprint**, выбрать публичный репозиторий `SHAN120186/CASH_Zuma`, ветку `main` и `render.yaml`. Сводка перед созданием должна показывать один web-сервис **Free**. Других платных ресурсов в файле нет.
7. В приватное поле `DATABASE_URL` вставить строку Neon с TLS. `JWT_SECRET` создаётся Render автоматически и должен сохраняться между обновлениями. Не менять его без необходимости: замена завершит сессии пользователей.
8. Запуск откажется работать с SQLite, без TLS, без постоянного JWT-ключа или без восстановленного активного администратора. Общий пароль по умолчанию не создаётся. Вход после переноса — под существующими учётными записями.
9. Проверить `/health`, `/ready`, `/version.json`, вход, права оператора/инвестора/директора, отчёт, документы и экспорт. Проверить с телефона при выключенном ноутбуке. Только после этого выдавать новый адрес сотрудникам.

## Обновления и резервные копии

- В Docker-образ включены клиенты PostgreSQL 18. На Windows отдельный `PG_BACKUP_BIN` указывает на каталог совместимых `pg_dump` и `pg_restore`. Не заменять `PG_BIN`: им также запускается существующий локальный сервер. Обновление клиента не обновляет и не мигрирует локальную базу.
- `worker.py --backup` сохраняет настройки TLS и channel binding из `DATABASE_URL`, передаёт пароль через окружение процесса и присваивает каждому архиву уникальное имя. Незавершённый архив не становится готовой копией; старые копии автоматически не удаляются. Ошибка старой версии клиента объясняет, какой параметр исправить.
- Проверка `pg_restore --list` проверяет читаемость архива, но не доказывает восстановление. Перед переключением выполнить реальное восстановление в отдельную базу той же старшей версии, сверить строки всех таблиц, последовательности и содержимое документов. Проверка базы со старым снимком не заменяет проверку последней копии перед переключением.
- Автоматическая публикация при push выключена. Сначала GitHub Actions должен завершить тесты и Docker build, затем в Render выбирается **Manual Deploy → Deploy latest commit**.
- `/health` проверяет процесс без обращения к базе; это не удерживает Neon активным постоянными проверками. `/ready` дополнительно проверяет PostgreSQL и используется при приёмке/диагностике.
- На Render нет постоянного локального диска. Нельзя хранить единственный backup, новые секреты или документы только в контейнере.
- Вложения операций уже сохраняются в PostgreSQL. Оригиналы старых XLSX финансовой модели из `data/models` необходимо сохранить отдельно; облачный перенос этой отложенной функции не входит в текущую публикацию.
- Фоновая рассылка не запускается. Для независимого резервирования нужен отдельный процесс или ручной экспорт с Neon с хранением копии вне Neon. Автоматическое независимое резервирование пока не настроено.
- При первом запуске сохраняются ограничения входа по логину и IP прокси. Недоверенные `X-Forwarded-For` не используются. Несколько неправильных входов через один прокси могут временно затронуть остальных пользователей — это следует проверить после размещения, прежде чем расширять доступ.
- Если квоты бесплатных тарифов будут исчерпаны, работа может приостановиться. Платное повышение тарифа автоматически не включать.

## Возврат при проблеме

Если в облаке ещё не было новых записей, отключить облачный сервис и открыть прежний сайт с сохранённой локальной базой. Если новые записи уже появились, сначала сохранить и проверить выгрузку из облака; переключение на старую копию без переноса этих записей потеряет изменения.

## Собственный домен позже

Покупка домена отдельно не заменяет сервер. После выбора и оплаты владельцем можно добавить домен в Render и направить DNS по подсказкам Render. Затем установить точный `PUBLIC_ORIGIN=https://ваш-домен` и повторно проверить вход/CSRF. Цены и доступность конкретного домена в этой поставке не подтверждены.
