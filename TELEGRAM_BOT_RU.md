# Telegram-бот Cash Zuma: что настроить на сайте

Бот — отдельный сервис (репозиторий `Cash_Zuma_Bot`). Сайт отдаёт ему только готовые данные через защищённый API `/api/bot/v1/…`. Права, компании и разрешённые группы проверяет сайт. Формат обмена описан в `API_CONTRACT_RU.md` репозитория бота.

## Переменные окружения сайта

| Переменная | Что это |
|---|---|
| `BOT_CLIENT_ID` | Имя сервиса бота, например `cash-zuma-bot`. В боте — `CASH_ZUMA_BOT_CLIENT_ID`. |
| `BOT_CLIENT_SECRET` | Секрет не короче 32 случайных символов. В боте — `CASH_ZUMA_BOT_CLIENT_SECRET`, то же значение. |
| `BOT_REPORT_GROUPS` | Группы для утренней сводки и их компании: `-1001234567890:UZGERMED,ZUMA`. Несколько групп — через `;`. |
| `TELEGRAM_BOT_USERNAME` | Имя бота без `@` (например, `ZumaPharm_Cashbot`) — для кнопки «Открыть бота» в профиле. |

Локально их задают в `config.local.env` (в Git не попадает), на Render — в Environment Variables. Пока `BOT_CLIENT_ID` и `BOT_CLIENT_SECRET` не заданы, API бота отвечает `503` и ничего не выдаёт. После изменения переменных сайт нужно перезапустить.

Секрет можно сгенерировать так:

```bash
python -c "import secrets; print(secrets.token_urlsafe(40))"
```

## Что получает группа

Утренняя сводка содержит только компании, указанные для этой группы в `BOT_REPORT_GROUPS`:

- остатки на начало дня по счетам и кассам;
- приход и расход за вчера;
- утверждённые платежи на сегодня и просроченные;
- заявки на проверке и утверждении;
- предупреждения о нехватке денег, минимальном резерве и превышенных бюджетах.

Валюты не складываются. Контрагенты, назначения платежей, номера счетов и документы в группу не передаются: вместо назначения указывается статья.

## Напоминания и привязка Telegram

1. Сотрудник открывает «Профиль → Telegram» и нажимает «Привязать Telegram».
2. Сайт показывает одноразовый код. Код действует 10 минут, новый код отменяет прежний.
3. Сотрудник отправляет боту в личном чате `/start КОД` или нажимает «Открыть бота».

Напоминание получает тот, чьё действие нужно сейчас, по роли в компании заявки:

- заявка на проверке — финансовый директор;
- на утверждении — директор;
- утверждённая банковская заявка — расчётный бухгалтер;
- утверждённая кассовая заявка — кассир.

Запасных получателей нет: если в компании нет сотрудника с нужной ролью, напоминание не отправляется. Администратор холдинга получает напоминание только при назначенной ему роли в этой компании. Учредитель напоминаний не получает. Автор заявки, её последний редактор и согласующие не получают напоминаний о действиях, которые им запрещены. Об оплате напоминают начиная с дня платежа, а не с момента утверждения.

Отключённый пользователь, пользователь без доступа к компании и пользователь, отвязавший Telegram, напоминаний не получают сразу. Смена или сброс пароля, отключение пользователя и изменение его прав тоже отвязывают Telegram: привязку нужно сделать заново. Код, отправленный по ошибке в группу, бот отменяет.

Каждое обращение бота записывается в журнал аудита: для сводки — в журнал каждой компании группы.
